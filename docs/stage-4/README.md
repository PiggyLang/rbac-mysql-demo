# 阶段四第一步：读取当前用户菜单

## 本步范围

新增 `GET /api/menus`，通过已认证 Session 中的用户名，依次关联 `user`、`user_role`、`role_menu` 和 `menu`，返回当前用户可见的菜单。查询每次请求都会访问数据库，使用参数化用户名条件、`DISTINCT` 去重，并按 `sort_order`、`code` 排序。响应字段为 `code`、`name`、`path`、`sortOrder`。

接口受现有“必须已认证”规则保护，不改变角色或权限授权配置；GET 请求无需 CSRF token。匿名请求返回 JSON 401。客户端提交的用户名不会参与身份选择，身份只来自 `Authentication.getName()`。响应仅包含菜单字段，不返回用户或凭据数据。

种子数据预期：alice 的 admin 角色可见 `users`（顺序 10）和 `reports`（顺序 20）；bob 的 reader 角色只可见 `reports`。菜单只控制导航展示，不构成 API 授权。用户 API 仍按权限码独立判断访问。
